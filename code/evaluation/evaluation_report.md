## 3. Failures found and improvements made

Iterations on the samples (all splits), each driven by the per-case diff from `score.py --details`:

| iteration | change | status acc. | step F1 | cost / 32 cases |
|---|---|---|---|---|
| 1 | first end-to-end run, all agents Haiku 5.5 | 71.9% | 0.764 | $0.26 |
| 2 | intake: deletion-verification follow-ups are deletion requests; separate second-opinion prompt; snapshot coverage inferred from row systems; INCOMPLETE without findings -> COMPLETE | 96.9% | 0.807 | $0.24 |
| 3 | reviewer/investigator accept the workflow-job primary profile; empty revisions rejected; retained security audit logs verified PRESENT; support attachments vs messages | 96.9% | 0.897 | $0.23 |
| 4 | invented / image-only ids dropped (ids must exist in participant data; image ids need a known prefix); findings must cite evidence that observes the resource; case-level retries for network errors | 96.9% | 0.883 | $0.23 |
| 5 | Sonnet 5.5 for investigator + planner (measured) | 100% | 0.914 | $1.33 |
| 6 | reviewer only when the contract guardrail reports issues (the always-on Haiku reviewer forced revisions in 46% of cases and lowered F1) | 100% | 0.916 | $1.07 |
| 7 (final) | all agents Haiku 5.5, review on issues, Sonnet only as escalation for persistent contract issues | 100% | 0.913-0.934 | $0.145 |

Failures that motivated the changes:

- **Intake false negatives** (5 samples): "please verify my deletion is complete" was read as a status question. The spec reserves NOT_APPLICABLE for access, correction, export, opt-out and other non-deletion actions; prompt fixed, plus a lexical cross-check with an independent second opinion.
- **Over-cautious status**: the planner returned INCOMPLETE with no findings because it could not prove unobserved systems were clean. Rule: INCOMPLETE requires an evidenced violation; enforced by the guardrail.
- **Absence evidence missed**: snapshot tables that do not name a system were not treated as covering it; coverage is now inferred from the rows' resources (gold cites such snapshots).
- **Invented resource ids** (file names, order and ticket numbers): steps on ids that exist in no participant data are dropped; screenshot records showing a display name are mapped through catalogue aliases (e.g. `object_19 (delivery_confirmation_19.pdf)`).
- **Unsupported findings**: findings citing an absence snapshot or a workflow claim (remediation-type activity) are rejected; evidence must observe the resource.
- **Noisy review loop**: an always-on reviewer rejected correct workflow-job links; now runs only when the contract guardrail reports issues.
- **Empty snapshot used as absence proof** (found by custom case custom_01): a snapshot with no rows at all was offered as evidence that a record was deleted and outweighed a failover replica that still held it; empty snapshots no longer count as absence evidence (custom cases went from 3/4 to 4/4 exact).
- **Escalation regression** (full run, case_61): the stronger model replaced a valid plan with an empty one; escalated plans are now accepted only when they are not worse.

Known remaining limitations (documented, not hidden):

- Concurrent workflow jobs with identical timing make some identifier-less resources (primary profiles, anonymised analytics records) genuinely ambiguous; ambiguous follow-ups are excluded (measured: including them added more false positives than true positives).
- A few sample gold resources appear in no participant-visible data and cannot be recovered without guessing.
- Category judgement for borderline records (e.g. analytics contact rows keyed by a historical hash) remains model-dependent.
